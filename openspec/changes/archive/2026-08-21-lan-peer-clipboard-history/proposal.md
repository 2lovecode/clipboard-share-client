## Why

用户需要在局域网内两台设备之间共享剪贴板内容，而又不想「对端一推就覆盖本机剪贴板」。当前客户端仅有 iced 列表与快捷键骨架，缺少发现、对等连接、口令校验与多媒体载荷同步。现在补齐完整共享闭环，使两端以历史列表为中介安全可控地交换内容。

## What Changes

- 增加局域网 **mDNS 服务发现**，并保留 **手动填写 IP/端口** 作为兜底连接方式
- 两端以 **对等（双方均可监听与拨号）** 方式建立 WebSocket 会话，连接时用 **简单共享口令** 校验
- 本机通过快捷键 **主动推送** 条目到对端；对端推送的条目进入本地历史；**剪贴板变化不自动入队**
- 历史列表展示来源与内容摘要；**用户点击某条后仅写入本机剪贴板**，不回传对端
- 载荷支持 **纯文本、图片、富文本/HTML**（不含文件投递）
- 在现有 iced UI 上接入连接状态、发现列表、口令配置与可点击历史项

## Capabilities

### New Capabilities

- `peer-connection`: 对等连接、mDNS 发现、手动 IP、口令握手与会话生命周期
- `clipboard-history`: 历史入队规则、点击写本机剪贴板、快捷键推送触发
- `clipboard-payload`: 文本 / 图片 / 富文本(HTML) 的编码、传输与写回剪贴板

### Modified Capabilities

- （无；仓库尚无主规格）

## Out-of-Scope / Non-goals

- 文件或文件夹投递
- 监听系统剪贴板变化并自动入队或自动同步
- 点击历史项后再次广播给对端
- TLS / 端到端强加密、账号体系、中继服务器
- 多于两台设备的房间模型或多方同步
- 跨广域网（非局域网）连通性保证

## Impact

- **代码**：`src/main.rs` 及后续拆分的网络、发现、历史、剪贴板模块；iced 视图与订阅
- **依赖**：现有 `warp` / `async-tungstenite` / `tokio` / `cli-clipboard` / `tauri-hotkey`；新增 mDNS 相关 crate；图片与 HTML 剪贴板平台能力可能需补充依赖
- **平台**：Windows（含 `deps/fetch_selected_text.exe`）、Linux、macOS 的剪贴板与发现行为需分别验证
- **安全**：口令仅提供局域网防误连；流量默认明文，依赖局域网信任边界
